# Свиньи с модульными лицами

`Svinki_Modular_Pigs.blend` — исходная сцена Blender. Три варианта созданы на
одной капсульной базе без одежды. Это настоящие меши, а не изображения.

- `01_Three_Pigs`: очки + закрученные усы; борода + обычные усы; пирсинг + прищур.
- `02_Modular_Master`: общая база и все сменные детали. По умолчанию видны
  открытые глаза и нейтральные брови. Остальные варианты скрыты.

## Сменные части

| Группа | Отдельные варианты / объекты |
|---|---|
| Глаза | `Eyes__Open`, `Eyes__Squint` |
| Брови | `Brows__Neutral`, `Brows__Raised`, `Brows__Confident` |
| Очки | `Glasses__Round` |
| Усы | `Mustache__Curled`, `Mustache__Classic` |
| Борода | `Beard__Short` |
| Серьга | `EarPiercing__Hoop` |
| Пирсинг брови | `BrowPiercing__Bar` |

Каждая строка-вариант — отдельный Empty с дочерними мешами, привязанными
к кости `Head`. Борода не объединена с усами. Два пирсинга независимы.
Одежды нет. Варианты можно комбинировать, оставляя только один вариант глаз,
бровей и усов. Очки, борода и пирсинг могут включаться независимо.

В Blender открой сцену `02_Modular_Master` и включай нужные корневые объекты
и их дочерние меши в Outliner. Для переключения через скрипт открой
`Tools/Blender/set_pig_appearance.py` в Scripting, отредактируй `ENABLED` и
нажми Run Script. При сохранении файла выбор сохранится.

## Экспорт для Unity

Файлы находятся в `Assets/Art/Characters/Pigs`:

- `Pig_Modular.fbx` — одна база и ВСЕ варианты лица, включая альтернативные глаза.
- `Pig_01_GlassesMustache.fbx`, `Pig_02_Beard.fbx`, `Pig_03_Piercings.fbx` — три
  готовых варианта без неиспользуемых аксессуаров.

В универсальном FBX включены все узлы. Перед показом модели выключи лишние
группы через `GameObject.SetActive(false)`. Например, для первого лица оставь
`Eyes__Open`, `Brows__Raised`, `Glasses__Round`, `Mustache__Curled`.
Для нового лица достаточно включить нужные группы на том же экземпляре.
В проекте уже подключены меню выбора лица с 3D-предпросмотром, сохранение
выбора и передача внешности через FishNet. Можно сочетать отдельные детали
или выбрать один из трёх готовых вариантов до начала раунда.

Сами FBX сохраняют связь групп с их мешами. При обратном импорте FBX именно
Blender автоматически переподчиняет skinned-меши скелету; для редактирования
групп используй исходный `.blend`. Отдельность мешей и веса при этом сохраняются.

Размер — около 2 метров с ушами, единицы — метры. В Blender впереди −Y;
FBX экспортирован с Y вверх и −Z вперед. Скелет — 16 костей, тип Generic,
простая A-поза, без дополнительных leaf bones и без готовых анимаций.
Тело соединено в один меш, аксессуары отдельные; UV-развёртка есть.
Материалы используют сплошные цвета без внешних текстур.
Unity настроен на Rig → Generic; материалы используют URP/Lit.

Привязка деталей к голове и сохранение структуры FBX проверяются скриптом
`Tools/Blender/validate_modular_pigs.py`. В обоих префабах игрока уже стоит
модульная свинья. `PigMotion` даёт простые движения при ходьбе, прыжке,
приседании и использовании фонарика. Это процедурные движения Generic-скелета;
готовые Humanoid-клипы автоматически не переназначаются.

## Выбор внешности в игре

Запускай сцену `Assets/Scenes/Lobby.unity`. Справа находится панель
«ТВОЯ СВИНЬЯ»: три готовых лица и независимые переключатели глаз, бровей,
очков, усов, бороды и двух пирсингов. Всего 288 сочетаний. Выбор сохраняется
на этом компьютере и применяется в одиночной игре и сетевом раунде.
Изменение лица в сетевом лобби снимает готовность; во время раунда выбор закрыт.

`Assets/Resources/Pigs/PigAvatar.prefab` — общий игровой аватар.
`PigAppearance.Apply(int)` переключает отдельные группы, не пересобирая меш.
Сетевой игрок получает выбранное лицо от сервера через SyncVar. Версия
протокола теперь 2, поэтому участникам нужны сборки с этим же изменением.

Старый человек сохранён в префабах как выключенный
`Character Visual Human Backup`. Для вида от первого лица создан отдельный
меш туловища без головы и копии копыт, использующие те же кости.
Повторная настройка доступна через меню Unity
`Svinki → Свиньи → Подключить модульного игрока` при остановленном Play Mode.
Проверки и их ограничения описаны в `Docs/Pig-avatar-validation.md`.

## Как Codex работает с Blender

В этой локальной сессии отдельное подключение не нужно: установленный
Blender запускает Python-скрипты через собственный `bpy`. Codex может
редактировать скрипт, пересоздавать сцену и открывать `.blend` в приложении.
Постоянный сервер, сетевой порт и сторонние расширения не устанавливались.

Пересоздание из терминала в корне проекта:

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python-exit-code 1 --python Tools/Blender/build_modular_pigs.py
```

Скрипт меняет только созданные им файлы свиней. Не запускай генератор
в существующей рабочей сцене через Run Script: он начинает с пустой сцены.
Для изменений внешности используй отдельный `set_pig_appearance.py`.
