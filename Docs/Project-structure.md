## Одежда

В `Content/Clothing`:

| Папка | Назначение |
|---|---|
| `Models` | Текущие модели, подогнанные под свинью, и используемые карты |
| `Generated/Definitions` | 33 актуальные карточки |
| `Generated/Pickups` | Текущие и сохранённые совместимые pickup-префабы |
| `Generated/Materials`, `Generated/Wearables`, `Generated/WearMeshes`, `Generated/GroundMeshes` | Подготовленные материалы, модели и меши |
| `Compatibility/Definitions` | 34 старые карточки с актуальными визуальными ссылками |
| `Compatibility/DisplayModels` | Две старые модели, на которые ещё ссылается сцена |
| `Templates` | Четыре первоначальные карточки и их модели |
| `Settings/ImportPolicy.asset` | Явно утверждённый набор из 33 предметов |

Сохранены 71 ID одежды, 38 псевдонимов оценки, GUID карточек и GUID/fileID корневых объектов 74 сетевых префабов. Pickup-префабы сохраняют свои карточки. FishNet пересчитал хеши, PrefabId и порядок регистрации; участникам нужна одинаковая обновлённая сборка. Каталог совместимости нужен прежним сохранениям.

Копирование FBX больше не публикует предмет автоматически. Для добавления выбрать модель и использовать **Svinki → Одежда → Добавить выбранные модели в каталог**. Для пересборки утверждённого набора — **Обновить библиотеку моделей**. Эта команда сохраняет существующие подогнанные меши. После изменения исходной геометрии через Unity MCP вызвать `PigClothingFit.RebuildAll()`, затем обновление библиотеки, `ClothingCompatibilityMigration.Apply()` и валидатор. Политика импорта не вычищает совместимые ID.

## Исходники, архив и удаление

При реорганизации все **328 первоначальных файлов `ArtSource`** были сохранены на прежних путях с совпадающими SHA256. После согласованной очистки удалены 152 служебных TXT/JSON-отчёта; оставшиеся 176 первоначальных файлов проверяются валидатором по размерам и SHA256. Дополнительно архивированы 169 файлов на 155,26 МиБ и 18 карт/вариантов на 27,34 МиБ: звук, животные, старые экспорты персонажей, модели одежды и карты материалов. Архив — в тематических подпапках `ArtSource`; recovery-сцена — в `Docs/Archive/Scenes/Recovery`.

Пакет `Universal Animation Library[Standard]` перенесён целиком в `ArtSource/Animations/UniversalAnimationLibrary`: 9 файлов, 60,70 МиБ, включая CC0-лицензию. Используемый FBX в `Assets` сохранён.

Удалены шаблонные `Readme.asset`/`TutorialInfo`, устаревший `SampleScene_NavMesh.asset`, копии текстур и опустевшие папки. Из профиля Volume убраны девять неподключённых тестовых подобъектов; основной список из 19 компонентов сохранён. В `PC_Renderer` сохранены реально существующие поля ресурсов и очищены только семь отсутствующих ссылок. Отсутствующая ссылка на стандартный Sprite Asset TMP заменена явным `null`.

48 архивированных материалов содержат обновлённые ссылки. Архив `Library/AssetRefactorBackup/before-refactor.zip` удалён; оставшиеся манифест и временные журналы находятся в `Library/AssetRefactorBackup` и не входят в Git.

## Проверки

Статическая проверка прошла: проверены 140 префабов и сериализованные ссылки. Нет отсутствующих GUID/скриптов и устаревших хешей; 71 ID одежды разрешаются. При проверке после реорганизации `SampleScene`/`FriendslopLobby` побайтово совпадали с резервной копией, включая 220/31 SceneId FishNet. Служебные отчёты рефакторинга удалены по решению пользователя.

Повторная проверка: **Svinki → Validation → Check asset refactor** или `AssetRefactorValidation.Run(true)` через Unity MCP. Результат выводится в консоль без создания файла.

Windows release-сборка успешна за 85 секунд: `Builds/Windows/Svinki.exe`, `Builds/Svinki-Windows.zip` (326 065 896 байт). Dev-сборка: 39,70 секунды, 0 ошибок, 16 существующих предупреждений об устаревших API/debug-шейдерах. Генерируемый Addressables `link.xml` исключён из подсчёта файлов.

При runtime-проверке семь проверок пройдены. Хост/клиент загрузили лобби с двумя аватарами и игровую сцену с 96 pickup-объектами каждый; одежда реплицировалась, снимок лобби отрендерен. Исходный checkpoint восстановлен, тестовые процессы остановлены. SQLite: сохранение, закрепление, повторное открытие изолированной базы; пять проверок атомарности/формата checkpoint пройдены.

Подключение через интернет/EOS и полное прохождение раунда не проверялись.

Временная development-сборка `Builds/AssetRefactorSmoke` сохранена: автоматическая проверка отклонила её удаление с сообщением `blocked by policy`. Готовая release-сборка и ZIP находятся отдельно в `Builds/Windows` и `Builds/Svinki-Windows.zip`.
