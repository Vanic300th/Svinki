# Проверка 2026-10-05

Среда: macOS Apple Silicon, Unity 6000.6.2f1, FishNet 4.7.3. Unity MCP проверен через initialize / tools/list / tools/call; редакторские операции выполнялись через MCP и CLI.

Проверено на редакторе-хосте и отдельных Development-процессах macOS с UDP транспортом:

- Хост входит в лобби без загрузки игрового уровня.
- Один готовый хост запускает раунд и создаёт контрольную точку.
- Поздний вход создаёт зрителя: участников двое, аватар один.
- Возврат в лобби удаляет аватары и выгружает SampleScene.
- Хост плюс пять клиентов занимают шесть мест. Седьмому вход отказан.
- Начать раунд без готовности гостей нельзя.
- Явный выход гостей сразу освобождает места.
- В следующем раунде прежний зритель получает игровой аватар.
- После короткого обрыва клиент автоматически возвращается к тому же NetworkObject (ID 17). Закрытый вход не мешает возврату.
- После истечения резерва 60 секунд аватар и участник удаляются. Повторный вход после открытия лобби — зритель.
- После выхода хоста локальный клиент получает сообщение завершения и возвращается в меню.
- Продолжение читает сохранённый номер раунда (2) и открывает новое лобби.
- Одиночный режим: один PlayerAvatar / GrayboxPlayerController, NetworkPlayer отсутствует. В меню ввод отключён.
- В сценах ровно один активный EventSystem.
- Без EOS-конфигурации онлайн выдаёт сообщение о настройке, снимает Busy и оставляет меню доступным.

Пять проверок SessionCheckpointVerification: чтение с одеждой и номером раунда, атомарная замена, сохранность предыдущего файла при несовместимой версии, повреждённый JSON, пустой JSON.

Собрана локальная macOS Development-версия с EOS_DISABLE. Настольные define symbols после тестовой сборки восстановлены. У WebGL установлен EOS_DISABLE. Нативные EOS SDK файлы для Windows/macOS/Linux присутствуют в установленном пакете; это проверка файлов, а не онлайн-подключения.

После заполнения конфигурации проверен настоящий EOS в редакторе macOS: Connect Device ID, создание лобби с кодом, подключение хоста через FishyEOS (один участник), выход с удалением лобби и возвратом в меню. Настройки Windows/macOS/Linux совпадают с рабочим `svinki-eos.json`. Новых ошибок при создании и выходе не зарегистрировано. Для Play Mode на Mac активирована macOS-цель; Windows-цель выбирала несовместимую Windows-библиотеку SDK.

Исправлено завершение EOS SDK: при остановке Play и уничтожении компонента освобождается платформа, а глобальный Shutdown выполняется только при завершении самостоятельного приложения, если SDK инициализирован этим кодом. SDK не поддерживает повторное использование после Shutdown в одном процессе. После перезапуска редактора проверены три последовательных цикла Play → создание настоящего лобби → выход → Stop; во всех случаях один участник, Busy снят, после выхода меню и освобождённое лобби.

Собрана Windows x64 Mono-версия с EOS, сцены Lobby и SampleScene, результат BuildReport — Succeeded, ошибок 0. Проверены PE AMD64-заголовки executable/UnityPlayer/EOS SDK, наличие нативных EOS DLL, онлайн-кода в Assembly-CSharp и совпадение упакованной конфигурации с рабочим svinki-eos.json. Оверлей отключён в настройках плагина, поэтому Windows bootstrapper не требуется. Сборка находится в Builds/Windows, архив для передачи — Builds/Svinki-Windows.zip.

Проверка тела и манекенов после исправлений: камера показывает свою кожу без головы при взгляде вниз; отдельный UDP-клиент создаёт второй аватар, его полная модель видна в редакторе-хосте на слое Default. Локальная копия тела использует FirstPersonBody, полная кожа своего игрока — LocalPlayerMirror; отражение исключает локальную копию и включает полную кожу. На хосте NavMesh содержит 346 вершин, все шесть агентов активны на сетке. Сталкер замер под взглядом (Frozen/Chase) и приблизился с z=10 до z=6.99 после поворота камеры (Moving/Chase). Гостевой Development-процесс после исправления запуска агентов не записал предупреждений «Failed to create agent» или исключений. В одиночке подтверждены локальная копия тела, шесть агентов на сетке, добавление одежды при подборе и повторный выход в меню без исключений FishNet.

Повторный раунд с тем же клиентом: раунд 2, два аватара в обоих процессах, 346 вершин NavMesh и шесть активных агентов на хосте, предупреждений навигации и исключений у клиента нет. После этих исправлений Windows x64 пересобран: Succeeded, ошибок 0, 20.9 секунды. В Assembly-CSharp присутствует FirstPersonBody, рабочая EOS-конфигурация упакована; архив Builds/Svinki-Windows.zip обновлён (56.1 MiB, 218 файлов без папки резервных символов Unity).

Не проверены: запуск Windows-сборки на Windows, вход со второго устройства, P2P/relay между разными сетями, сборки Linux/WebGL, длительная игра с задержками/потерями, аварийное убийство интернет-хоста, визуальная проверка одежды и фонаря на двух разных устройствах. См. MULTIPLAYER.md.
