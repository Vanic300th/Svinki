# Постоянные фотографии и манекены стартового зала

Фотографии каждого игрока автоматически записываются в локальную SQLite при съёмке. Файл: `Application.persistentDataPath/Photos/photos.sqlite`. Он находится вне репозитория и папки сборки. База содержит сами JPEG 300×200, идентификаторы, время сохранения и назначения шести слотов шкафчика. Это локальное сохранение; переноса между компьютерами или облачной базы нет.

В альбоме (`P`) кнопка `ROUND / SAVED` переключает последние 12 фотографий забега и постоянный архив. Шкафчик выбирает снимки из постоянного архива. Сохраняются последние 120 уникальных фотографий плюс более старые снимки, закреплённые в шести слотах. Переход в новый забег, выход из сессии и закрытие игры не очищают базу. Одинаковые JPEG не дублируются. Текстуры архива декодируются по мере просмотра, а не все одновременно.

Игроки на одном устройстве используют локальный профиль установки. Для существующих multiplayer-тестов аргумент `--profile <name>` выбирает отдельный локальный профиль в той же SQLite; это соответствует изоляции локальных тестовых клиентов. Имя игрока и номер назначенного ему шкафчика не используются как ключ сохранения. SQL-параметры связаны через prepared statements, JPEG хранятся в BLOB.

## Сеть

Постоянный архив остаётся локальным. Результаты забега по-прежнему показывают только фотографии текущего раунда через существующий канал FishNet. На сервер не загружается весь архив.

После подключения игрок восстанавливает только шесть слотов своего шкафчика. Изображения отправляются через существующий FishNet broadcast-механизм по 1 KB, по событию, с ограничением 32 KB на снимок. Хост получает владельца из соединения, проверяет фазу лобби, принадлежность шкафчика, последовательность частей и размер JPEG до декодирования. Ручное назначение и очистка дополнительно требуют близости к шкафчику и свободной линии взаимодействия. Восстановление разрешено один раз для каждого слота соединения; новые загрузки ограничены одной в секунду, активная сборка — одна на соединение.

Принятые назначения реплицируются остальным участникам и обслуживают late join через существующий session cache. Локальная SQLite обновляется после подтверждённого хостом изменения собственного слота. Первичный снимок состояния комнаты не перезаписывает локальные назначения до их восстановления. Архивы других игроков и чужие фото из результатов никогда не записываются в локальное сохранение.

Протокол повышен с 21 до **22** из-за нового `SavedLockerUpload`: всем участникам нужна одинаковая обновлённая версия игры. FishNet, транспорт, EOS и система матчей сохранены.

## SQLite и платформы

- macOS Editor/Player используют системную `/usr/lib/libsqlite3.dylib`.
- Windows x64 Editor/Player используют официальный `sqlite3.dll` из `Assets/Plugins/SQLite/Windows/x86_64`.
- Linux desktop использует системную `libsqlite3.so.0`, которая должна быть установлена.
- Windows ARM, Android, iOS и WebGL этим проходом не подключены.

Windows DLL скачана с [официального сайта SQLite](https://www.sqlite.org/download.html), SHA3-256 архива проверена. Источник и хэши записаны в `source.json`; SQLite находится в [общественном достоянии](https://www.sqlite.org/copyright.html). PluginImporter ограничивает DLL Windows x64, включая Windows Editor; на macOS она не загружается. Ошибки записи показываются в альбоме/шкафчике и журнале, без молчаливой подмены базы памятью. Перед удалением или переносом базы игру нужно закрыть: SQLite использует WAL и может иметь соседние `-wal` и `-shm` файлы.

## Стартовая комната завода

В `SampleScene` добавлена группа `Graybox Level/Arrival room AFK displays`: шесть дополнительных обычных манекенов по краям зала прибытия лифта. Переиспользованы существующие модель, `ThrowableMannequin`, `NetworkThrowableMannequin` и сетевой трансформ. У них нет `MannequinBrain`, `ThiefBrain` или `MannequinHeadWatcher`. Они неподвижны до взаимодействия, их можно переносить и бросать, а при падении за карту они возвращаются домой.

Маркер `FixedFactoryDisplay` исключает этих манекенов из случайного размещения `RoundWorldLayout`. Остальной пул не менялся: 80 случайных нейтральных, 16 агрессивных, 10 воров и 8 наблюдателей. Теперь всего 86 нейтральных и 120 манекенов всех типов. Все 214 ранее существовавших сетевых ID завода сохранены; шесть новых объектов получили уникальные ненулевые ID.

## Проверка

`Tools/Unity/PhotoPersistenceSetup.cs` настраивает native plugin и размещает манекенов через Unity Editor API. `PhotoPersistenceCheck.Storage` проверяет настоящую SQLite, повторное открытие, сохранность байтов и слотов, изоляцию профилей, deduplication и ограничение архива с защитой закреплённых фото. `PhotoPersistenceCheck.Offline` проверяет съёмку, reset раунда, просмотр архива, назначение/очистку и восстановление слота через повторно открытый тестовый файл. Тестовые фотографии отделены от пользовательской базы.

Пройдены проверки:

- настоящая SQLite: повторное открытие, сохранность JPEG и слотов, изоляция профилей, bound SQL, deduplication, ограничение 120 и защита закреплённых снимков;
- обычный offline: съёмка, reset раунда, архив, назначение/очистка, восстановление после повторного открытия базы, один активный EventSystem;
- обычный локальный FishNet Host: загрузка сохранённого JPEG через client broadcast, подтверждение и запись слота в SQLite, повторное открытие, отказ повреждённому/слишком большому JPEG и удалённому ручному запросу, восстановление картинки через snapshot download и подтверждённая очистка;
- обычный offline-лифт → завод: шесть неподвижных манекенов на заданных местах после shuffle, отсутствие атакующего AI, перенос/отпускание существующей системой, сохранность постоянного альбома;
- 64 seed / 7 360 свободных достижимых размещений существующего случайного пула; 251 уникальный ненулевой NetworkObject ID в игровых сценах.

Отчёты находятся в `ArtSource/PhotoPersistence`, `ArtSource/PhotoRound/spawn-validation.txt` и отчёте существующей проверки сцен. Тестовая SQLite удалена после остановки Play Mode; пользовательский архив не изменялся. Отдельный удалённый клиент и reconnect с новой системой сохранения в этом проходе не запускались; сетевой тест использовал настоящий локальный Host и его клиент. Windows-билд не выполнялся.
