# Свинки: сессия с друзьями

Хост запускает сервер внутри игры. Остальные вводят шестизначный код. Онлайн использует EOS Lobbies для поиска хоста и EOS P2P (с автоматической ретрансляцией) для FishNet; игрокам не нужны аккаунты, IP-адреса и настройка роутера. Настольные платформы: Windows/macOS/Linux. Веб-версия — одиночная, с `EOS_DISABLE`.

## Настройка EOS разработчиком

Онлайн требует бесплатный проект в [Epic Developer Portal](https://dev.epicgames.com/portal/). Пока реквизиты не заполнены, меню выдаёт понятную ошибку; одиночная игра и локальные тесты доступны.

1. Создать продукт, Sandbox, Deployment и клиент с политикой для Connect (Device ID / создание пользователя), Lobbies (создание, поиск, вход, выход, удаление, kick) и P2P. Использовать клиентскую политику, не серверные административные ключи. Для тестовой среды предоставить тестерам доступ к Sandbox согласно настройкам портала.
2. В Unity открыть `EOS Plugin > EOS Configuration` и заполнить продукт, окружение и клиент для Windows/macOS/Linux. Это требуется нативному упаковщику EOS Plugin 6.2.0.
3. Скопировать `Docs/svinki-eos.example.json` в `Assets/StreamingAssets/svinki-eos.json`, заполнить теми же реквизитами. Игра создаёт собственный EOS Platform без оверлея и выполняет Connect DeviceID. Этот файл игнорируется Git; в настольной сборке он должен присутствовать. Клиентские EOS credentials распространяются с игрой; административные секреты туда не помещать.
4. Открыть `Lobby`, нажать Play, создать лобби. Второй компьютер с теми же Product/Sandbox/Deployment должен войти по коду. Для проверки EOS нужны разные устройства: DeviceID на одном устройстве соответствует одному профилю.

Документация: [EOS Lobbies](https://dev.epicgames.com/docs/epic-online-services/multiplayer/lobbies-and-sessions/lobby-interface/lobbies-guide/lobbies-guide-intro), [EOS P2P](https://dev.epicgames.com/docs/epic-online-services/multiplayer/nat-p2p-interface), [EOS Plugin](https://github.com/EOS-Contrib/eos_plugin_for_unity).

## Правила сессии

- Всего 6 мест, включая хоста, зрителей и зарезервированные места.
- Все участники отмечают готовность. Хост начинает раунд; можно играть одним хостом.
- Каждый раунд заново загружает `SampleScene` и стартовый комплект. Хост вручную завершает раунд через меню Esc. Для будущих условий победы/поражения есть публичный `NetworkLobby.EndRound()`.
- Вошедший во время раунда наблюдает за игроками до следующего раунда. Стрелки влево/вправо переключают цель. Зритель не имеет аватара и не участвует в AI/подборе.
- При потере связи во время раунда аватар остаётся в мире, место резервируется на 60 секунд. Клиент пытается подключиться каждые 3 секунды. Возвращающийся профиль получает прежний аватар и одежду. Закрытие входа не блокирует этот возврат. После истечения резерва аватар удаляется; новый вход — зрителем.
- Выход и исключение освобождают место сразу. Исключённый профиль не допускается обратно в эту сессию.
- Уход хоста заканчивает сессию у всех. Миграции хоста нет.
- Движение считает клиент владельца, FishNet NetworkTransform передаёт позицию. Взгляд, приседание и фонарь передаются отдельным состоянием. AI, предметы и одежду изменяет хост.

## Контрольная точка

`Application.persistentDataPath/round-checkpoint.json` записывается до старта каждого раунда. Содержит версию, сцену, номер раунда, идентичности, имена и начальную одежду. Запись через временный файл и атомарную замену: при ошибке сохранения раунд не начинается. Это начало раунда; текущие позиции, AI и предметы не сохраняются.

«Продолжить» создаёт новое лобби и код. Состав участников может измениться. Старые профили получают начальную одежду из сохранения, новые — стандартную. Следующий раунд возвращает стандартные комплекты. «Создать лобби» заменит сохранение только при первом старте раунда. Повреждённое сохранение выдаёт ошибку; можно начать новую игру.

## Локальная проверка без EOS

- Editor: `Lobby` → Play → F8 запускает хост. F9 подключает клиент к localhost.
- `Svinki > Build macOS test client` создаёт временную локальную Development-сборку с отключённым EOS. Обычные настольные сборки через Build Profiles должны включать EOS и настроенное окружение.
- Сборку запустить с `--local-join --address 127.0.0.1 --port 7770 --profile guest1 --nickname Друг`. Хост: `--local-host`. Для продолжения локального теста вызвать `NetworkLobby.Instance.DebugHost(true)` через Editor.
- `--profile` разделяет тестовые локальные идентичности на одной машине. Локальный UDP транспорт служит только проверке; код `LOCAL1` не является интернет-кодом.
- Development-драйвер: `--session-test-path /tmp/svinki-guest1`; состояние пишется в `.state`, команда JSON `{"action":"ready"}` в `.command`. Поддержаны ready/start/end/close/kick/leave/disconnect/quit. В release драйвер отсутствует.
- `SessionCheckpointVerification.Run()` через Unity eval проверяет чтение/замену файла, сохранность при несовместимой версии, повреждённый JSON и пустой файл.

## Ассеты и сборки

`Svinki > Configure friend sessions` настраивает префабы: клиентское движение, сохранение аватара при обрыве, Multipass (UDP тест + EOS), офлайн-персонаж и шрифт меню. Не выполнять во время Play. После добавления новых NetworkObject выполнить `Svinki > Rebuild FishNet scene IDs`.

Для новой одежды сохранить `ClothingDefinition` в каталоге NetworkPlayer. Идентификатор одежды — имя ассета, поэтому сохранять уникальность и стабильность имён.

Пакеты закреплены: FishNet 4.7.3, EOS Plugin 6.2.0. Адаптер FishyEOS включён исходниками из commit `91593266f0750ea55e810626903c2ebc3a78750d`, лицензия и изменения находятся в `Assets/ThirdParty/FishyEOS`.

Перед выпуском обязательна проверка EOS между разными сетями и платформами, отключений на 10/65 секунд, аварийного закрытия хоста, конфликтного подбора одежды, поведения AI и задержек/потерь пакетов. Локальный UDP тест не подтверждает работу EOS в интернете.
