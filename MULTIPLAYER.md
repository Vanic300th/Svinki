# Мультиплеер Svinki

Сетевой фундамент работает на FishNet 4.7.3. Игроки скачивают обычную сборку игры, подключаются к одному выделенному серверу по IP и UDP порту, затем создают комнату или входят по шестизначному коду. На сервере одна комната соответствует отдельному экземпляру `SampleScene`; лимит задаётся в компоненте `NetworkLobby` (сейчас 4, допустимо 2–4). Коды живут в памяти процесса сервера и исчезают при перезапуске.

## Проверка без удалённого сервера

1. Открыть `Assets/Scenes/Lobby.unity` и нажать Play.
2. Нажать «Локальный сервер для проверки», затем «Создать комнату».
3. Для второго игрока запустить клиентскую сборку на той же машине и подключить её к `127.0.0.1:7770` с кодом комнаты.

## Сборки и запуск

- В Build Profiles сделать клиентскую сборку для Windows/macOS/Linux. Первая сцена уже `Lobby`, вторая `SampleScene`.
- Отдельно сделать Linux Dedicated Server build в Unity Build Profiles. Запускать его в batch/headless режиме, например с аргументом `--port 7770`; без аргумента используется UDP 7770. Сервер автоматически стартует при `Application.isBatchMode`.
- На текущем Mac установлен модуль сборки macOS, но нет модуля Linux Dedicated Server. Перед Linux-сборкой нужно установить этот модуль через Unity Hub. Headless-запуск проверен на macOS.
- На серверной машине открыть выбранный UDP порт в firewall и настроить публичный IP/DNS. В клиенте указать адрес и тот же порт. На itch.io публикуется клиентская сборка; сервер работает отдельно.
- Коды комнат действуют только на том сервере, к которому подключён клиент. Для нескольких серверов понадобится общий список комнат или роутер матчей.

## Что уже синхронизируется

- Создание и вход в комнаты, лимит игроков, появление отдельного персонажа у каждого участника.
- Движение, прыжок, бег и приседание: клиент отправляет ввод, сервер двигает персонажа и рассылает положение.
- Подбор одежды: сервер проверяет расстояние, направление взгляда и препятствия; предмет исчезает для всех в комнате. Одежда появляется только на боковом манекене подобравшего игрока.
- Комнаты используют отдельные физические сцены; предметы из разных комнат не взаимодействуют.

## При добавлении одежды

Добавить `ClothingDefinition` и модель в сцену по существующему образцу, поставить на предмет `PickupItem`, `ClothingPickup`, `NetworkObject` и `NetworkPickup`. В префабе `Assets/Prefabs/NetworkPlayer.prefab` добавить новый `ClothingDefinition` в `Clothing Catalog`. После добавления сетевых объектов выполнить `Svinki > Rebuild FishNet scene IDs` в редакторе.

## Следующий этап перед публикацией

- Проверить две отдельные клиентские сборки против Linux Dedicated Server, включая повторный вход, две одновременные комнаты и подбор одной вещи двумя игроками.
- Протестировать задержку и при необходимости добавить предсказание движения: сейчас движение серверное, поэтому на удалённом сервере может чувствоваться задержка.
- Настроить ограничения числа комнат, логирование и перезапуск сервера на хостинге. Текущий лимит ограничивает игроков **в комнате**, а не суммарную нагрузку процесса.
- При необходимости добавить TLS/защиту трафика и авторизацию. Сейчас подключение по IP и коду комнаты без учётных записей.
